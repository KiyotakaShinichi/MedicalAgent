### Additional finding discovered during the audit (not in the external list)

**Tracked files are rewritten by ordinary test runs.** Running the offline suite
dirties the worktree in three distinct places, all tracked in git:

| Path | What rewrites it |
|---|---|
| `.coverage` | binary SQLite coverage DB, rewritten by any `pytest --cov` |
| `tests/_tmp_drift/latest_eval_drift_report.json` | a test writes it on every run (timestamp churn) |
| ~17 files under `Data/evals/**`, `Data/complete_synthetic_training/**` | evaluation artifacts regenerated by their tests |
| 8 tracked `__pycache__/*.pyc` files | rewritten whenever their source module is imported |

This is a systemic issue, not three unrelated ones: **a developer cannot run the
test suite and still have a clean worktree.** It feeds directly into the
release gate's clean-worktree requirement and into the weak-history finding,
because it pressures contributors either to commit regenerated noise or to
routinely discard changes by hand. Fixing it means untracking the transient
artifacts (`git rm --cached` plus gitignore) and pointing the drift test at a
temp directory — outside this sprint's three scope items, and recommended in §10.

## 2. Dependency update automation — ADDED

`.github/dependabot.yml` (new). Four ecosystems, all **review-based**:

| Ecosystem | Directory | Grouping | PR limit |
|---|---|---|---|
| `uv` (Python; `uv.lock` is the resolver of record) | `/` | minor+patch grouped | 5 |
| `npm` | `/frontend-react` | dev and prod grouped separately | 5 |
| `github-actions` | `/` | all grouped | 3 |
| `docker` | `/` | — | 2 |

Design decisions:

- **No auto-merge, and no auto-merge workflow was added.** A dependency bump in
  a system running safety evaluation and ML inference can move model output or
  refusal routing without failing a type check.
- **Majors excluded for `numpy`, `pandas`, `scikit-learn`, `torch`,
  `transformers`.** Upgrading these can shift evaluation metrics and invalidate
  frozen evidence; they belong in separately-evidenced migrations, not a bot PR.
- **`uv` rather than `pip`.** `pip` would update `pyproject.toml` without
  updating `uv.lock`, which would then fail CI's `uv lock --check`.

Verified: YAML parses (`yaml.safe_load`), and all four target manifests
(`pyproject.toml`, `uv.lock`, `frontend-react/package-lock.json`, `Dockerfile`,
`.github/workflows`) exist at the declared paths.

**Not verifiable locally:** that GitHub accepts the `uv` ecosystem on this
repository's instance. Dependabot config errors surface in the repository's
Insights → Dependency graph → Dependabot tab; that needs a check after push.

## 3. Ruff configuration — EXPANDED

### Exact rules, before and after

```diff
- select = ["E9", "F63", "F7", "F82"]
+ select = ["E4", "E7", "E9", "F", "B"]
+ ignore = ["B008", "B905"]
+ [tool.ruff.lint.per-file-ignores]   # E402 exemptions, 8 explicit entries
```

### The suggested `E, F, I, UP` was measured and rejected as specified

Enabling those four families produces **8,950 violations**, overwhelmingly
cosmetic — which is precisely the "mass formatting or unrelated churn" the same
brief forbids. Measured breakdown:

| Family | Hits | Disposition |
|---|---:|---|
| `E501` line-too-long | 6,762 | **Rejected** — pure reformatting, no defect signal |
| `I` import sorting | 959 | **Rejected** — ordering churn across nearly every file |
| `UP` pyupgrade | 756 | **Rejected** — 535 are `timezone.utc` → `UTC` cosmetics |
| `SIM` simplify | 64 | **Rejected** — refactors live code for style; higher risk than value on a safety path |
| `B008` function-call-in-default | 301 | **Ignored** — FastAPI `Depends()` idiom; false positive by construction |
| `B905` zip-without-strict | 39 | **Ignored, deliberately not bulk-fixed** — the autofix writes `strict=False`, freezing today's silent-truncation behaviour into source. In a codebase that zips predictions against labels, that is a per-call-site review question. |
| `E402` module-import-not-at-top | 196 | **Exempted per-file** — 180 in `scripts/` are the `sys.path` bootstrap that must precede `backend.*` imports; the 10 in `backend/` are late imports breaking genuine circular dependencies (one already carried an explanatory comment) |
| `E4`, `E7`, `E9`, `F`, `B` (rest) | **294** | **Enabled, and every violation fixed** |

Every rejection is recorded inline in `[tool.ruff.lint]` with its measured count,
so the decision is auditable rather than asserted.

### The 294 violations, all fixed

| Rule | Count | How |
|---|---:|---|
| `F401` unused-import | 215 | ruff safe autofix |
| `F841` unused-variable | 21 | 19 removed by hand after reviewing each; 2 preserved as documented latent defects |
| `F541` f-string-no-placeholder | 13 | ruff safe autofix |
| `B033` duplicate-value | 10 | ruff safe autofix |
| `F405` star-import hazard | 10 | replaced `import *` in `dep001d_integrity.py` with explicit re-exports |
| `E712` `== True` | 6 | `.eq(True)` — these are **pandas elementwise masks**, so a truthiness check would have been wrong |
| `E702` semicolon statements | 5 | split |
| `E701` colon statements | 4 | split |
| `B007` unused loop variable | 3 | renamed to `_name`, or dropped a pointless `enumerate` |
| `B020` loop var overrides iterator | 3 | renamed loop targets in `hybrid_prediction.py` |
| `F402` import shadowed by loop var | 2 | renamed `field` → `field_name` (was shadowing `dataclasses.field`) |
| `B023` loop-variable capture | 1 | default-arg binding in `risk_engine.py` |
| `E741` ambiguous name `l` | 1 | renamed to `latency` |

**Total suppressions added: 5**, each with a written reason:

- 3 × `# noqa: F401` in `support_chat_agent.py` — the module is a deliberate
  re-export facade (see §6, regression 2).
- 2 × `# noqa: F841` marking **latent defects preserved for domain review**:
  - `breastdcedl_xai.py` builds a feature-meaning lookup table and never
    consults it, so every feature renders as the generic fallback. Wiring it up
    would change clinician-facing XAI text — a behavioural change, not a lint fix.
  - `compound_intent_router.py` computes `normalize_user_text(message)` then
    splits the **raw** message. Switching would change intent routing, which is
    safety-relevant.

Both are labelled `LATENT DEFECT` in the source with an explanation of why they
were documented rather than silently deleted or silently fixed.

## 4. Fresh-clone / offline reproducibility — ADDED AND TESTED

### What was actually run

A real `git clone` into a scratch directory, with this sprint's changes applied
as a patch, then executed **with no `.env` present**:

```
[PASS] required_tracked_files: all present
[PASS] required_tracked_dirs: all present
[PASS] no_dotenv_required: no .env present; offline path must not need one
[PASS] ruff_config_self_contained: select = ['E4', 'E7', 'E9', 'F', 'B']
[PASS] offline_test_subset_present: 3 files
[PASS] config_imports_without_secrets: backend.config imported
[PASS] offline_test_subset_passes: 40 passed, 1 warning in 26.78s
```

Independently confirmed in the clone: `backend` resolved from the clone's own
path (not the source tree), and `ruff check backend scripts tests` passed using
only the clone's `pyproject.toml`.

### What was added

- **`scripts/check_fresh_clone_offline.py`** — structural checks plus an
  optional `--run-tests` execution of a designated offline subset, and a
  machine-readable `--json-output` artifact.
- **`tests/test_fresh_clone_offline_check.py`** — 11 contract tests. These
  verify the checker *fails* on a simulated incomplete clone; a verifier that
  always passes manufactures confidence rather than providing it.
- **CI step** in the fast `static-quality` job. The CI checkout is itself a
  fresh clone with no `.env`, so it is the one place the contract can be proven
  rather than asserted. Purely additive — no existing step was modified.
- **`CONTRIBUTING.md`** — a "Verifying a fresh clone" section, a lint policy
  section, and a dependency-update policy section.

### Claim boundary — stated explicitly, in the script and its output

This verifies **repository content sufficiency**: that the offline path needs no
secret, no populated `.env`, no prebuilt RAG index, and no network. It does
**not** verify dependency resolution or installation — that remains covered by
`uv lock --check` and `scripts/check_dependency_contract.py`. The full pinned
environment was **not** reinstalled from scratch; the existing venv was reused.
Conflating those two is how "reproducible" gets claimed without evidence.

## 6. Regressions found — both introduced by this sprint, both fixed

Enabling `F` caught real dead code, and also broke two things. Both were caught
by the full suite and are recorded here rather than quietly repaired.

**Regression 1 — `tests/test_env_documentation.py`.** My new script read
`PATH`, `SYSTEMROOT`, `TEMP`, and `TMP` via `os.environ.get(...)` to build a
minimal subprocess environment. The repository enforces that every
source-referenced environment variable is documented in `.env.example`, so the
gate failed. **Fixed by making the check stronger, not by weakening the gate:**
the script now strips every variable `.env.example` declares from a copy of the
real environment, which proves independence from app configuration *and* names
no OS variable.

**Regression 2 — `tests/test_breast_monitoring.py`.** `support_chat_agent.py`
ends with three late-import blocks that exist to **re-export** helpers split out
of it; callers and tests reach them as `support_chat_agent.<name>`. `F401` saw
them as unused and removed three, breaking
`support_chat_agent._looks_truncated_reply`. Fixed by restoring the three names
with `# noqa: F401` and a comment explaining the facade.

**Systematic follow-up.** Rather than trusting that the suite caught every
instance, all 211 `(module, name)` pairs derived from removed import lines were
cross-checked against every `<module>.<name>` reference in `backend/`,
`scripts/`, and `tests/`. Only the one already-fixed case matched.

## 10. Remaining blockers and the single recommended next sprint

Remaining, in priority order:

1. Coverage floor at 35% vs 69.89% measured.
2. Five backend modules ≥ 958 LOC.
3. Running the test suite dirties ~19 tracked files (`.coverage`,
   `tests/_tmp_drift/*.json`, `Data/evals/**`) — a clean worktree and a
   completed test run are currently mutually exclusive.
4. Mypy covers 5 modules, not the backend.
5. Release gate still `BLOCKED_RELEASE` (6 decision failures; licensing).

### Recommended next sprint — ratchet the backend coverage floor

Single, narrow, deterministic, externally verifiable, and already evidenced by
two independent measurements in this sprint (69.89%).

- Raise `--cov-fail-under` from 35 to a conservative **60**, leaving ~10 pp of
  headroom rather than pinning to the measured value.
- Add per-module floors for the safety-critical paths that must not silently
  lose coverage.
- Make a test run leave the worktree clean: untrack `.coverage`,
  `tests/_tmp_drift/`, and the 8 tracked `__pycache__/*.pyc` files
  (`git rm --cached` plus gitignore), and redirect the drift test's output to a
  temp path. This directly relieves the clean-worktree release blocker and makes
  the coverage ratchet meaningful — a floor is hard to trust when running the
  suite that measures it also rewrites ~21 tracked files.
- Record the measurement and the ratchet policy so the floor rises with real
  coverage instead of being set aspirationally.

Deliberately excluded from that sprint: god-file decomposition, which needs its
own equivalence-evidenced change.
