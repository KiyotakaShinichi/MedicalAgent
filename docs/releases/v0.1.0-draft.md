# NLCare v0.1.0 development release draft

Status: **BLOCKED_RELEASE**

This draft describes a possible first repository development release. It is not
a healthcare product release and must not be tagged while the blockers below
remain unresolved.

## Intended scope

- Reproducible local synthetic-only engineering demonstration.
- FastAPI and React/TypeScript application with role-scoped demo workflows.
- Source-governed RAG, bounded tool workflows, synthetic temporal ML/MLE, trace
  diagnostics, and release-gated engineering evidence.
- No real patient care, PHI, diagnosis, treatment, prognosis, medication,
  genetic-risk, tumor-marker, or clinical decision authority.

## Release blockers

1. DEP-001 remains `BLOCKED_BEHAVIORAL` on immutable consumed evidence.
2. The canonical release gate currently reports 6 decision failures and 25
   appendix warnings across 257 artifacts. The local complete offline suite is
   green (1,772 passed; 69.91% combined branch-aware coverage), but CI must
   reproduce it on the final reviewable tree.
3. The repository has no root source-code license, and third-party KB/data
   redistribution is not cleared.
4. The worktree contains substantial pre-existing uncommitted evaluation work,
   so a clean, reviewable release commit does not exist yet.

## Tag procedure after blockers close

1. Run the complete verification stack in `CONTRIBUTING.md` on a clean branch.
2. Confirm release-gate evidence points to immutable, current artifacts.
3. Confirm no consumed holdout or one-shot bank was rerun or modified.
4. Resolve code licensing and produce a distributable-asset manifest.
5. Move the relevant `Unreleased` entries in `CHANGELOG.md` to `0.1.0` with the
   actual release date.
6. Create an annotated `v0.1.0` tag only after review.

Passing these engineering conditions would still not establish clinical
validation, healthcare compliance, clinician approval, patient benefit, or
production healthcare readiness.
